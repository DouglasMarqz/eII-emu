# Hardware evidence and unresolved details

2026-10-17. OCR used only to locate text. Important chip names, connections
and the IC135 feedback topology were checked on enlarged rendered pages.

## Source documents inspected

- E-mu Emulator II service manual: architecture 2-2, scanner 2-4,
  main CPU 2-9, DRAM 2-11, microcontroller 2-13, output channels 2-17.
- Schematics 7-6 through 7-19: scanner CPU/CTC/PIO and main CPU/CTC/DMA,
  inter-CPU wiring, state counter and both PROM latches.
- Channel 1 schematic 7-45: 6072 DAC, SSM2045 and S3528 path.
- SRAM map attachment: corroborating memory ranges; individual attachment
  mapping still needs full visual cross-check before relying on any discrepancy.

The service description says the main CPU controls filter/VCA envelopes.
Output control voltages are DAC-generated and multiplexed into sample-and-hold
circuits. This calls for firmware control plus analog modeling, not replacing
the original envelopes with a convenient generic ADSR generator.

The prose contains apparent component/reference inconsistencies (for example
the main-CPU discussion vs the CTC/DMA schematic). Schematics and actual firmware
transactions must resolve these; OCR or text alone is not treated as authority.

## IC135 / IC137

Both supplied files are 512 bytes. They match the required physical capacities,
but their identity is user-supplied; no physical chip readback was performed.

IC135 addresses:

| Input | Connection |
| --- | --- |
| A8 | Previously latched UCD15 |
| A7 | Previously latched UCD14 |
| A6..A4 | UCNT2..UCNT0 |
| A3 | -MPRQ.1 |
| A2 | -MPRD.1 |
| A1 | CHSL3 |
| A0 | UREQ.1 |

Its outputs are UCD15..UCD08. IC137 addresses A8=CHSL3,
A7..A5=UCNT2..0, A4=UREQ.1, A3=PRECAR, A2=LOOPMD,
A1=DECFLG, A0=BACKMD; outputs UCD07..UCD00.
Both latches must sample the previous state simultaneously. The implementation
currently models this lookup/latch block only, not the entire state counter,
register-file datapath or DRAM bus grants.

## Evidence from firmware execution

The scanner writes LCD control at low port BE and data at BF; boot-banner text
appears in the I/O trace generated by executing its original ROM. The initial
LCD subset was grounded in those transactions and the documented 8-bit display
interface. Complete LCD busy/CGRAM/shift timing is not implemented.

Both CPUs configure PIO port A to bidirectional mode. The floooh PIO core has
unfinished bidirectional/handshake behavior, so it was not silently reused as a
complete device. The local register model is explicitly provisional; its
handshake and interrupt logic remains a bring-up blocker.

The SCN2651 diagnostic interface is register-level. Input is separated by a
provisional 4167-CPU-clock character interval so the ROM's output flow-control
polling does not swallow an entire instantaneously delivered command. This is
not an implemented baud-rate generator or serial-bit transport.

## Disk input distinction

The supplied OS31 and OS31HD .E2O files are 72,704 bytes each; the memory-test
.emuiifd file is 573,440 bytes. They are retained as different input types.
No guessed sector geometry, direct OS RAM injection or fake disk-ready boot
completion has been added. SIO/DMA and disk framing are still unimplemented.
