# 0.61 vector front panel

The owner confirms 0.60 no longer fills an entire Windows CPU thread. Preserve
that working baseline. Sequence Play investigation is explicitly deferred while
this front-panel milestone is evaluated; no claim that Play CPU cost is solved.

## Design and implementation

The owner's three front-panel photographs were visually inspected. The complete
bare overlay establishes group proportions; closeups establish keypad order,
legends, switch/LED placement and colors. The new default top-level window draws
an original scalable reconstruction in native GDI+ paths, text, gradients and
procedural LCD dots. No photograph or bitmap skin is loaded by the application.
Original photographs are not redistributed. This is a first reconstruction,
not a claim of exact typography, surface texture or manufacturer vector artwork.

The 1960x760 logical layout includes Master Control, Sequencer, Enter, Filter,
VCA/LFO, Voice Definition, Preset Definition, Real Time Control, Special/Disk
and Sample. The beige/navy/red visual language follows the supplied reference.
The number pad is 1,2,3 / 4,5,6 / 7-No,8,9-Yes / 0. Buttons and LEDs use independent
existing ScannerButton/ScannerControls mappings. The firmware still generates
the LCD and decides button behavior; no canned boot display or menu is added.

Native geometry and the portable SVG preview share vector_panel_layout.h.
The SVG is a labeled design preview, not evidence of a running Windows build.
It is generated by tools/export_vector_panel.cpp and rendered for visual QA.
Actual GDI+ rendering and fonts still require target Windows verification.

## Operation

- Default window resizes with aspect-preserving letterboxing; per-monitor DPI
  notifications resize the vector surface. The current display glyph function
  is reused for the live 2x16 LCD.
- Mouse down/up and Space down/up on a focused key reach real scanner contacts.
  Tab cycles hardware switches. Top-row/numpad digits and Enter address the
  physical number/Enter contacts. Capture/focus loss releases held switches.
- Four vertical sliders and left/right wheels drive the existing 0..5 V inputs.
  Drag or mouse-wheel adjust them. MIDI-driven wheel positions remain visible.
  A dragged control is not pulled backward by a stale worker snapshot.
- Mix Out Volume is a host output trim 0..1, applied at AudioQueue consumption.
  Default 1 bypasses multiplication and preserves PCM bits. It is saved in the
  existing user preferences as OutputVolume. It is not a calibrated analog pot.
- Input Gain is drawn inactive and labeled recording pending; the sampling
  analog input/recording gain circuit is not invented by this UI.
- Settings / Devices opens the previous thin settings/diagnostics view with
  ROM/disk selectors, audio/MIDI devices, capture and startup options. Closing
  that settings view hides it. Closing the vector window exits the application.
- Filter Service, Boot/Reset, Run/Pause and All Notes Off use the existing host
  command paths. Saved paths/devices/calibration/sliders remain compatible.

## Performance boundaries

A window-size-resolution cache holds the static vector rendering. It is rebuilt
on resize, not on a periodic animation timer. Only changed LCD/LED/control/status
regions are invalidated. Dynamic drawing respects the paint clip, and LCD dot
commands are skipped outside the LCD clip. There is no new renderer thread or
frame-rate loop; the existing snapshot cadence is retained. The cache is an
output rasterization of vector commands, not an unscalable background image.

No Z80, controller, scheduler, wait fix, MIDI transport, filter or solver code
is changed. The audio transport adds only the host trim at the consumer boundary.
The target-machine GUI CPU cost remains unmeasured here.

  to separate text,LEDs and switches. GDI+ runtime is not inferred from SVG.
